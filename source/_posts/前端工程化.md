# 前端工程化
了解前端工程化从认识「编译原理」开始，编译本质就是把「一些字符串」转换成「另外一些字符串」
编译原理步骤：
1. 词法分析(sourceCode -> tokens) 
2. 语法分析(tokens -> ast)
3. 代码转换(ast -> newAst)
4. 代码生成(newAst -> newCode)
基于以上我们举一些常见的case：
1. Typescript：Typescript代码 -> Javascript代码
2. babel：ES6语法 -> 有兼容性的语法（polyfill）
3. rollup：多文件代码 -> 单文件代码（依赖分析+TreeShaking）
4. webpack：一个万物皆打包的架构，支持通过各种loader打包各种各样的资源（css-loader、vue-loader、图片字体等），同时提供热更新、本地开发、懒加载、分包等能力，真正进入工程化时代。
5. esbuild：也是打包架构。用go写的，比webpack更快，但生态不如webpack。
6. vite：相比webpack，主打极快启动和更好的热更新机制。
7. vue、react、跨端：本质也是编译，tempalte -> vue代码，jsx -> React代码，跨端 -> 对应平台可运行的代码

## 什么有了webpack还有esbuil和rollup
- esbuild：webpack底层是js，单线程，而esbuild用了go语言，可以并发的读取依赖文件，并发的做代码转换。
- rollup：webpack基于webpack module展开，因此不仅会有anything->webpack module的时间成本，也有注入webpack runtime的空间成本，rollup直接基于esm打包，又快又干净。

## 为什么需要打包(工程化)
1. 多资源整合，把项目内img，font，css，js，ts，vue等，整合成一个产物
2. 有些资源需要加工
- ts要变成js，所以需要ts-loader
- js要兼容浏览器版本，所以需要babel-loader
3. 需要对产物进行优化
- 分chunk包，做首屏加载优化，用split-plugin
- 对产物进行代码压缩，terser
- 减小不必要的包引入，tree-shaking

## webpack

#### 核心运行流程
1. 解析插件配置，初始化Compiler实例，注册所有的插件（可以在各个生命周期回调）
2. 从入口文件开始，生成依赖图（解析文件内容、生成AST），然后对于每个依赖根据后缀匹配用对应的loader去解析，递归的完成解析和转换
3. 对处理后的结果做分chunk，对每个chunk做代码优化（TreeShaking、模块去重、代码压缩等）

#### 基本配置
以下是commonjs写法，把package.json里的type改为module则也能用es module的方式写
```javascript
module.exports = {
  // 1. 入口配置
  entry: {
    // 多入口：key 是 chunk 名，value 是入口文件
    main: './src/main.js',
    // 可选：拆分第三方库（如 vue/react）
  },

  // 2. 输出配置
  output: {
    // 打包后的文件根目录（绝对路径）
    path: path.resolve(__dirname, 'dist'),
    // 文件名：[name] 对应 entry 的 key，[contenthash] 内容哈希（缓存优化）
    filename: isProduction ? 'js/[name].[contenthash:8].js' : 'js/[name].js',
    // 非入口 chunk（如异步加载的模块）的命名
    chunkFilename: isProduction ? 'js/[name].[contenthash:8].chunk.js' : 'js/[name].chunk.js',
    // 静态资源的公共路径（CDN 部署时用，如 'https://cdn.example.com/'）
    publicPath: '/',
    // 清空输出目录（替代 CleanWebpackPlugin，Webpack 5+ 内置）
    clean: true
  },

  // 3. 模式
  mode: isProduction ? 'production' : 'development',

  // 4. 模块处理（loader）
  module: {
    rules: [
      // 4.1 JS/TS 处理（Babel 兼容）
      {
        test: /\.(js|jsx|ts|tsx)$/, // 匹配文件后缀
        exclude: /node_modules/, // 排除 node_modules
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env'], // 转换 ES6+ 语法
            plugins: [
              ['@babel/plugin-transform-runtime', { corejs: 3 }] // 复用辅助函数，减小体积
            ],
            cacheDirectory: true // 缓存编译结果，加快二次构建
          }
        }
      },

      // 4.2 CSS 处理（支持 Less/Sass）
      {
        test: /\.(css|less)$/,
        // loader 执行顺序：从右到左（css-loader → postcss-loader → less-loader → style-loader/MiniCssExtractPlugin）
        use: [
          // 开发环境用 style-loader（注入到 HTML），生产环境抽离成单独 CSS 文件
          isProduction ? MiniCssExtractPlugin.loader : 'style-loader',
          {
            loader: 'css-loader',
            options: {
              modules: false, // 关闭 CSS Modules（如需开启设为 true）
              importLoaders: 2 // 让 @import 的 CSS 文件也经过 less-loader 和 postcss-loader 处理
            }
          },
          'less-loader' // 处理 Less（Sass 用 sass-loader）
        ]
      },

      // 4.3 图片/图标处理
      {
        test: /\.(png|jpe?g|gif|svg|webp)$/i,
        type: 'asset', // Webpack 5+ 新特性，替代 url-loader/file-loader
        parser: {
          dataUrlCondition: {
            maxSize: 8 * 1024 // 8KB 以下转 base64，减少请求；以上输出文件
          }
        },
        generator: {
          // 输出路径和命名
          filename: 'assets/images/[name].[hash:8][ext]'
        }
      },

      // 4.4 字体/媒体文件处理
      {
        test: /\.(woff2?|eot|ttf|otf|mp4|webm|mp3|wav)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'assets/[name].[hash:8][ext]'
        }
      }
    ]
  },

  // 5. 插件配置
  plugins: [
    // 生成 HTML 文件（自动引入打包后的 JS/CSS）
    new HtmlWebpackPlugin({
      template: './public/index.html', // 模板文件
      filename: 'index.html', // 输出文件名
      title: 'Webpack 配置示例', // HTML 标题
      inject: 'body', // JS 注入到 body 底部
      minify: isProduction ? { // 生产环境压缩 HTML
        removeComments: true, // 移除注释
        collapseWhitespace: true // 折叠空白
      } : false
    }),

    // 生产环境抽离 CSS 到单独文件（开发环境用 style-loader 无需此插件）
    isProduction && new MiniCssExtractPlugin({
      filename: 'css/[name].[contenthash:8].css',
      chunkFilename: 'css/[name].[contenthash:8].chunk.css'
    }),

    // 复制静态资源（如 public 下的 favicon.ico）
    new CopyWebpackPlugin({
      patterns: [
        {
          from: path.resolve(__dirname, 'public'),
          to: path.resolve(__dirname, 'dist'),
          filter: (source) => !source.includes('index.html') // 排除模板文件
        }
      ]
    }),

    // 定义全局变量（如 process.env.VUE_APP_API_BASE_URL）
    new DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify(isProduction ? 'production' : 'development'),
      'process.env.API_BASE_URL': JSON.stringify('https://api.example.com')
    })
  ].filter(Boolean), // 过滤掉 false 的插件（如开发环境的 MiniCssExtractPlugin）

  // 6. 开发服务器
  devServer: {
    host: 'localhost', // 主机名
    port: 8080, // 端口
    open: true, // 启动后自动打开浏览器
    hot: true, // 开启热更新（HMR）
    compress: true, // 开启 gzip 压缩
    historyApiFallback: true, // 解决 SPA 路由刷新 404 问题
    // 接口代理（解决跨域）
    proxy: {
      '/api': {
        target: 'https://api.example.com', // 目标服务器
        changeOrigin: true, // 改变请求源
        pathRewrite: { '^/api': '' } // 重写路径（如 /api/user → /user）
      }
    }
  },

  // 7. 解析配置
  resolve: {
    // 路径别名（简化导入，如 import '@/utils' → 对应 src/utils）
    alias: {
      '@': path.resolve(__dirname, 'src'),
      'components': path.resolve(__dirname, 'src/components')
    },
    // 省略文件扩展名（导入时无需写 .js/.vue 等）
    extensions: ['.js', '.vue', '.json', '.less'],
    // 模块查找路径（优先 node_modules）
    modules: [path.resolve(__dirname, 'node_modules')]
  },

  // 8. 优化配置（生产环境为主）
  optimization: {
    // 生产环境压缩 JS/CSS
    minimizer: [
      `...`, // 保留 Webpack 默认的 JS 压缩器（TerserPlugin）
      new CssMinimizerPlugin() // 压缩 CSS
    ],
    // 代码分割（拆分第三方库和业务代码）
    splitChunks: {
      chunks: 'all', // 分割所有 chunk（同步+异步）
      cacheGroups: {
        // 拆分第三方依赖
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          priority: -10 // 优先级（数值越大越先拆分）
        },
        // 拆分公共代码
        common: {
          name: 'common',
          minChunks: 2, // 至少被 2 个模块引用
          priority: -20,
          reuseExistingChunk: true // 复用已有的 chunk
        }
      }
    },
    // 运行时 chunk 分离（避免内容哈希变化）
    runtimeChunk: {
      name: (entrypoint) => `runtime-${entrypoint.name}`
    }
  },

  // 9. 开发工具（source-map）
  devtool: isProduction ? 'source-map' : 'eval-cheap-module-source-map',
  /* 
  devtool 选型建议：
  - 开发环境：eval-cheap-module-source-map（快+准）
  - 生产环境：source-map（完整源码，或 hidden-source-map 隐藏源码）
  */

  // 10. 性能提示（可选）
  performance: {
    hints: isProduction ? 'warning' : false, // 生产环境提示大文件
    maxEntrypointSize: 500 * 1024, // 入口文件最大 500KB
    maxAssetSize: 500 * 1024 // 单个资源最大 500KB
  }
};
```

#### 自定义lodaer和plugin
loader本质上是函数，自定义loader示例如下：
```javascript
function diyLoader(source) {
    const resultStr = transfer(source); // source 为文件原始内容，这里就是把文件原始内容做编译，将结果返回

    return resultStr; // 举例: import 'xxx.vue' => 真实的经过转后后的vue业务代码
}
```
plugin本质是类，自定义plugin示例如下：
```javascript
class DiyPlugin {
    apply(compiler) {
        // compiler是webpack的核心类，上面有一些整个webpack生命周期的狗子，比如下面这里就是完成打包后的钩子(done)
        compiler.hooks.done.tap('DiyPlugin', (compilation) => {
            // compilation 是产物内容，比如comilation.assets会用key，value表示打包的产物们，key是文件名，value是文件内容
            // 举例比如在spa项目，我们要把打包的js文件，引入到模板html文件
            const html = compilation.assets['index.html'];
            const jsFiles = Object.keys(compilation.assets)filter(item => item.endsWith('.js')); // 找到所有js文件
            const resultHtml = html.replace('<%= js %>', jsFiles.map(file => `<script src="${file}"></script>`).join('\n'))

            compilation.assets['index.html'] = {
                source: () => resultHtml,
                size: () => resultHtml.length
            }
        });
    }
}
```


#### 热更新
1. 初始化阶段：
   正常构建一遍产物 → 起 HTTP 服务，产物写入内存 → 浏览器访问服务，HTTP 服务器从内存取产物返回展示；
   同时启动 WebSocket 服务，浏览器建立连接。

2. 运行阶段：
   - 未开启热更新：监听到文件变化 → 重新全量构建产物 → 写入内存 → WebSocket 通知浏览器「刷新页面」；
   - 开启热更新：监听到文件变化 → 增量编译变化模块 → 生成更新描述（manifest）+ 新模块代码（update chunk）→ WebSocket 通知浏览器 → 浏览器下载新代码，基于模块ID替换内存中旧模块 → 执行 accept 回调。
   （Vue-loader帮用户自动做了accept回调，大致内容其实就是不销毁组件，template变化时重新render，js变化时更新变更的data、method、props，style的话直接替换）

## vite
> 基于esbuild+rollup，同时依靠es module编译能力

#### 核心运作流程
- 开发环境
1. 读取 vite 配置，先通过 esbuild 对 node_modules 内的依赖做预构建（将 CommonJS/UMD 格式转为 ESM 格式，同时合并零散依赖文件以减少请求数）；
2. 启动基于 Koa 的开发服务器，访问 localhost:端口 时默认返回项目根目录的 index.html；
3. 依据浏览器原生 ES Module 特性，index.html 入口文件中的所有 import 会向服务器发起请求获取对应资源；
4. 开发服务器接收请求后，对不同资源实时编译并返回：
- JS/TS：通过 esbuild 实时编译（含路径别名解析）后返回；
- CSS：编译后通过 JS 动态在 <head> 插入 <style> 标签（CSS-in-JS 形式）；
- 图片 / 字体 / 音视频：直接返回二进制内容（带缓存控制）；
- 同时通过 WebSocket 实现热更新（HMR），仅更新变更模块。

- 生产环境
1. 读取 vite 配置，以 Rollup 为核心打包工具、esbuild 为辅助工具构建产物；
2. Rollup 负责核心打包逻辑：代码分割、Tree Shaking、产物拆分、静态资源处理；
3. esbuild 负责快速编译 / 压缩：TS 转 JS、ES6+ 语法降级、代码压缩（替代 Babel/Terser）；
4. 最终输出纯静态产物：CSS 抽离为独立文件（而非 CSS-in-JS）、JS/TS 打包为 ESM 格式（支持代码分割）、静态资源添加哈希后缀。

### 热更新
流程基本和webpack一致，都是服务器通知更新 -> 客户端拉取 -> 客户端替换对应模块 -> 执行对应回调(accept/import.meta.hot)
- 差异点类比：
可以把 HMR 比作 “图书馆更新一本书”。
Webpack 思路：图书馆先把所有书打包成 “合集册”（chunk），每本书贴一个唯一编号（模块 ID）。更新某本书时，不能直接换书，要先把新书做成 “更新册”（热更新 chunk），标注 “替换合集册里编号 5 的书”，再让管理员（运行时）按编号找到位置替换。
Vite 思路：图书馆不做合集册，每本书都单独放在书架上（原生 ESM 文件），更新某本书时，直接把新书放到原位置，读者（浏览器）直接拿新的就行，无需编号、无需做更新册。
